## 目标与边界

让用户在 Qiaomu Reader 中阅读可提取文本的英文内容时，直接完成“悬浮看简释 → 点击查详情或选中查短语 → 主动加入复习 → 在 Spaced Repetition 中复习”的闭环。Qiaomu 负责阅读、查词和创建卡片；Spaced Repetition（下称 SR）负责复习队列、间隔和调度数据。

Language Learner 是词典和复习实现的参考，不是运行时依赖。本项目不修改 Language Learner，也不读取或覆盖它的 `data.json`、词汇笔记和 `review.md`。需要移植的代码逐项核对来源与许可证；定制版保留 Qiaomu Reader 的 GPL-3.0-only 许可、原作者署名和第三方声明，并明确标识其派生来源。

## 官方版与定制版并存

定制版使用独立插件 ID，以便和官方 `qiaomu-reader` 同时安装。插件 ID 与测试库名称是两个独立概念：本项目的真实测试库固定命名为 `qiaomu-reader-english`，路径为 `F:/qiaomu-reader-english`；定制版插件 ID 在首次正式安装前单独确定，此后视为持久数据和链接的身份，不因改名方便而随意更换。插件名称明确标注定制版，不冒充官方更新。

只修改 `manifest.json` 的 ID 不足以并存；实施时必须逐项隔离：

- 阅读、书库和 AI 视图类型，以及新增的协议路由和回跳链接使用定制版身份。原有 `obsidian://qiaomu-reader` 链接继续由官方版处理，定制版不接管旧路由。命令和上下文事件要确认以新 ID 为来源。
- 两个插件的 `data.json` 会因插件目录不同而分开，但 Qiaomu 当前的 `reading-progress.json` 和 `reading-highlights.json` 默认可写在库根或同一个书籍目录；定制版必须给进度、高亮、恢复文件和复习文件设置独立命名空间，不能只依赖新插件目录自动隔离。
- 官方版保留 EPUB、PDF 等现有默认文件关联。定制版从自己的书库、命令或明确标注的文件菜单项打开文件；两个插件不同时注册同一扩展名。Markdown 也仅通过定制版显式打开，不改变 Obsidian 默认编辑器。
- 两版可以只读同一批电子书，但对书籍 frontmatter、阅读笔记、摘录、封面缓存及设置引起的写入要逐项审计和隔离。不能把官方版的进度和高亮文件当作定制版的共享数据库；如需沿用旧记录，提供备份后显式导入，不静默搬迁或双写。
- 检查全局 CSS 与 DOM 标识是否会跨插件影响阅读界面。定制版样式限定在自己的根容器内；并存时两个阅读视图、弹窗和侧栏互不误操作。

源码开发保留两条线：上游跟踪 Qiaomu 官方更新，定制分支维护英文学习模块和少量阅读器接入点。定期把上游更新合入定制分支，解决实际冲突并执行回归；最终安装和交付的始终是合并验证后的定制版。上游更新不直接覆盖定制插件，定制功能也不写回上游线。独立 ID 解决安装身份冲突，不保证源码合并永远没有冲突。

## 用户流程

1. 用户在 Qiaomu 打开电子书、带文本层的 PDF，或从 Markdown 文件菜单选择“在 Qiaomu Reader 中阅读”。原生 Markdown 编辑入口保持不变。
2. 桌面端鼠标停在英文单词上约 200 毫秒，单词附近显示简短释义。快速掠过、离开单词、滚动、翻页或切换文件时，待发查询和弹窗及时取消；弹窗不能挡住当前选文或造成翻页。
3. 点击单词打开完整查词面板；选中短语后通过现有选区工具栏查询整个短语。查词不自动保存单词、创建划线或打开 AI。
4. 查词结果中，用户主动点击“加入复习”，可确认或编辑词条、释义和原句。保存成功后给出可核验反馈；同一 Qiaomu 复习文件中的同一规范化词条更新现有卡片，不重复创建。
5. 用户在 SR 原有入口复习。Qiaomu 不新增“开始复习”按钮，也不实现自己的间隔算法。
6. 手机和平板没有悬浮动作：点击单词或长按选词进入同一查词流程。桌面窄阅读区也不能让查词面板遮住正文或选区操作。

## 内容范围

| 格式 | 阅读入口 | 查词条件 |
| --- | --- | --- |
| EPUB、FB2、FBZ、MOBI、AZW、AZW3 | Qiaomu 现有入口 | 正文成功提取为文本时支持悬浮、点击和选区查词 |
| PDF | Qiaomu 现有入口 | 仅有可定位文本层的页面支持查词；缩放、文本选择和原页码保持可用 |
| CBZ | Qiaomu 现有入口 | 仅存在实际可提取文本时支持；纯图片页面没有查词入口 |
| Markdown (`.md`) | 文件右键菜单/命令显式打开 | 新增只读阅读适配，支持渲染后的英文正文查词 |

本轮不做 OCR。扫描 PDF、图片中的文字和通常为图片的 CBZ 页面继续可读，但不展示无法执行的查词动作。也不把 `.md` 注册为 Qiaomu 的默认打开方式。

Markdown 阅读使用 Obsidian 原生 Markdown 渲染，保留标题、段落、列表、引用、代码、图片、内部链接等基础结构。读源文件而不改源文件；外部编辑后的刷新不得丢失当前阅读位置。书内位置以文件路径、标题/块位置及必要的文本片段记录，不伪造 EPUB CFI 或 PDF 页码。

## 查词体验与词典

- 复用 Qiaomu 已有的选区、工具栏和翻译入口；“查词”与现有整句翻译是不同动作，不建立第二套相互竞争的选区控件。
- 悬浮卡显示最多三条简释，并提供发音及进入完整查词的入口。点击查词面板显示词形、音标、释义、例句和当前阅读原句；网络加载、无结果、超时、失败与重试都要有明确状态。
- 词典查询引擎、Vue 词窗和面板、词汇学习及对应设置按 Language Learner 1.2.16 原功能移植，覆盖其在线、AI 和本地 MDict 来源；AI 服务配置按上方的共享 Qiaomu AI 决定执行。网页解析型来源的稳定性需分别验证。
- 本地 MDict 及 MDD 资源沿用用户选择的文件，但 Qiaomu 自行保存词典配置，不直接读取 Language Learner 私有设置。当前 MDict 实现只覆盖桌面端；移动端要明确显示不可用，不能假称所有词典跨端一致。
- 查词来源及调用时机遵循 Language Learner 原有设置；启用 AI 词典来源时，点击查词可能发起 AI 请求。悬浮查词使用原版词窗和词典顺序，不另加 Qiaomu 专属的词典来源策略。
- 远端词典和 MDict 返回的 HTML 视为不可信内容：禁止脚本执行，限制链接、资源和样式作用域；切词后的旧请求不能覆盖新词结果。

## 复习数据与所有权

定制版沿用 Language Learner 的词汇库、词汇笔记、单词数据库与复习数据库结构，默认路径位于 `Qiaomu Reader/`，并保留原版状态、词形、标签、笔记、例句、备份及恢复能力。Spaced Repetition 仍负责复习调度；移植模块同步其排程和状态，不读取或覆盖原 Language Learner 插件的数据文件。

新测试库从空库开始，SR 的标签、分隔符和调度存储模式以该库安装后的实际配置为准。原 `F:/languagelearner` 库使用 `#flashcards` 标签、`?` 多行卡片分隔符和笔记内调度数据，仅作为兼容性参考，不复制其设置到新库。实现须检查目标库实际配置，生成 SR 能识别的卡片；不能把某个库的配置硬编码为所有用户的默认配置。词条的正面标识保持稳定，改释义或例句不应无故重置排程。

添加和更新只修改 Qiaomu 所拥有的卡片区域，并通过 Obsidian Vault API 对目标文件串行处理；保留未知字段、手工正文、其他卡片及现有 `<!--SR:...-->` 标记。发生冲突或目标不符合预期时停止写入并说明恢复办法，不重建整份文件。首次创建、路径变更、同步失败和重载后恢复都需要验证。

卡片保存词条、释义、原句、书名、文件路径及格式对应的位置。来源链接仅在能实际回到原文时生成；位置失效时提示用户重新定位，不静默跳到错误内容。加入复习成功必须由目标文件读回且 SR 实际识别卡片来确认。SR 未安装或未启用时，查词仍可用，但复习入口给出明确状态，不宣称已经进入复习队列，也不自动安装插件。

Qiaomu 文件内去重；不会悄悄修改 Language Learner 的卡片。因此两插件同时收录同一词时，SR 可能出现两张卡。这是独立运行方案的已知限制。若未来要求两插件共享同一词库，需另行设计明确的数据所有者和迁移路径，不能让两个插件共同重写一个文件。

## 交互与性能约束

- 不改变 Qiaomu 现有主题、分页、PDF 缩放、划线和批注行为。阅读正文中的命中检测不能给整本书常驻包裹逐词 DOM，或让翻页/字号变化明显变慢。
- 悬浮、点击、选区、翻页、拖动选择、PDF 平移和弹窗操作之间不能互相误触发。弹窗关闭与窗口/阅读视图卸载时清理监听器、定时器和未完成请求。
- 设置保留 Language Learner 原有的查词、词汇学习和复习选项；AI 服务商和连接由 Qiaomu 统一配置，学习专用提示词仍可编辑。没有配置本地词典时，在线来源仍可工作；离线时给出真实状态。
- 只在用户主动保存时写入卡片；阅读、悬浮和选区预览不写文件。网络词典查询仅传输当前查询词或明确选择的内容，不默认上传整本书。

## 实施顺序

1. 建立所有可提取文本格式共用的词命中与选区接口，并将 Markdown 作为独立只读适配加入 Qiaomu。先验证阅读、翻页、链接及选区无回归。

3. 加入专属 SR 卡片文件与“加入复习”，验证去重、并发、手工修改保护、来源回跳，以及真实 SR 复习后进度不丢失。

## 验收标准

- 在 EPUB、FB2/FBZ、MOBI、AZW/AZW3、带文本层 PDF 和 Markdown 中分别找一处实际英文文本，验证悬浮/点击/选区；纯图片 PDF、CBZ 页面不出现虚假的可用查词动作。
- 200 毫秒左右悬浮触发；快速扫过不发起多次无效查询。切词、滚动、翻页、关闭视图后没有残留弹窗或过期结果。鼠标移入弹窗可操作发音和详情。
- Markdown 从显式入口打开；返回 Obsidian 编辑器后源文件字节不变。标题、图片、内部链接和外部更新的重新渲染正确。
- 在线词典成功、无结果、断网/超时及重试；本地 MDict 首次加载、重复查询、缺少 MDD 和错误文件分别验证。桌面与移动端支持范围如实呈现。
- 同一词重复加入只保留一张 Qiaomu 卡片；例句和来源可读、可回跳。用户手工修改的其他卡片、SR 注释和现有 Language Learner 文件保持不变。
- 官方版与定制版同时启用时，两个书库和阅读视图都能打开；默认电子书打开方式仍属于官方版，定制版从明确入口打开。两版的进度、高亮、设置、回跳链接和样式相互隔离，读写前后核对官方版文件字节不变。
- 在 SR 1.15.4 的真实界面看到新卡、完成一次复习、重载 Obsidian 后仍保留调度；再更新该词释义和例句，调度及手工内容不丢失。检查 SR 存储模式切换后的兼容性，无法支持时明确阻止危险同步。
- Qiaomu 定制版的真实 Obsidian 测试只使用新库 `F:/qiaomu-reader-english`，不再使用 `F:/languagelearner`；后者仍是 Language Learner 项目的指定测试库。新库不复制旧库的笔记、插件设置或凭据。安装候选前备份受影响的插件资产、设置及目标复习文件，使用明确命名的测试记录；单元测试和构建在 Qiaomu 源码 checkout 完成。
